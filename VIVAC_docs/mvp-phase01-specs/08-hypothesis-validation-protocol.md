## 2. 본 문서의 목적과 위치

### 2.1 목적
Phase-1 출시 후 **무엇을 측정하고, 어떤 기준으로 성공/실패를 판단하며, 결과에 따라 어떻게 행동할지**를 사전에 정의합니다.

### 2.2 왜 사전에 정의하는가
- 출시 후 데이터를 보고 가설을 만들면 **확증 편향** 발생
- 의사결정 기준이 흔들림 ("애매한 결과 → 우리에게 유리한 해석")
- 다음 단계(Phase-2) 우선순위 결정의 기반이 흐려짐

### 2.3 다른 문서와의 관계
- **PRD**: 가설을 정의 (H1, H2, H3)
- **이벤트 트래킹 설계**: 가설 검증에 필요한 데이터 수집
- **본 문서**: 검증 방법론, 기준선, 의사결정 분기

## 3. 검증 가설 요약 (PRD 재명시)

| 가설 | 명제 | 유형 |
|---|---|---|
| **H1** | 통합 장소 데이터가 BPL/UL 백패커의 탐색 시간을 줄여준다 | Value Hypothesis |
| **H2** | 5단계 온보딩 설문으로 의미있는 사용자 세그먼트를 확보할 수 있다 | Data Hypothesis |
| **H3** | 카테고리 빠른 필터가 텍스트 검색보다 선호된다 | UX Hypothesis |

## 4. 검증 기간 및 단계

### 4.1 전체 일정

```
[D-7]    출시
   ↓
[D 0~6]  Stabilization Window (제외 구간)
   ↓
[D 7]    측정 시작 — 베이스라인 측정 시작
   ↓
[D 7~13] Week 1 — 베이스라인 확정 + 가설 1차 측정
   ↓
[D 14~27] Week 2~3 — 가설 본격 검증
   ↓
[D 28]   1차 의사결정 (Phase-2 우선순위 결정)
   ↓
[D 28~]  지속 모니터링
```

### 4.2 Stabilization Window (D 0~6)

출시 직후 7일은 데이터 분석에서 제외:
- 초기 마케팅/공지로 인한 비정상 트래픽
- 버그 수정에 따른 데이터 변동
- 호기심 클릭 등 비전형 행동

> 💡 단, 시스템 안정성 모니터링은 D-Day부터 즉시 시작.

### 4.3 의사결정 시점

| 시점 | 의사결정 |
|---|---|
| **D 14** | Mid-checkpoint: 명백한 실패 가설 조기 식별 |
| **D 28** | Final-checkpoint: Phase-2 우선순위 결정 |
| **D 56+** | Quarterly review |

## 5. 가설 H1 — 통합 데이터 가치

### 5.1 명제 (정량화)

> "BPL/UL 백패커는 통합 장소 검색을 통해 짧은 시간에 의사결정을 내릴 수 있다"
>
> 측정 가능 형태:
> - 검색 → 상세 진입 전환율이 30% 이상
> - 세션당 평균 상세 페이지 방문 수가 2개 이상
> - 평균 세션 길이가 3분 이상

### 5.2 측정 지표

#### 주 지표 (Primary)

| 지표 | 정의 | 데이터 소스 |
|---|---|---|
| **검색→상세 진입 전환율** | `place_card_clicked` / `search_executed` | PostHog |

#### 보조 지표 (Secondary)

| 지표 | 정의 | 데이터 소스 |
|---|---|---|
| 세션당 평균 상세 진입 수 | session 내 `place_detail_viewed` 평균 | PostHog |
| 평균 세션 길이 | session duration 중앙값 | PostHog / GA4 |
| 검색→상세→이탈 비율 | 상세 진입 후 즉시 이탈 비율 | PostHog |

### 5.3 성공 기준

| 등급 | 기준 |
|---|---|
| 🟢 **Strong Positive** | 전환율 ≥ 40% AND 세션당 상세 ≥ 2.5 |
| 🟡 **Positive** | 전환율 ≥ 30% AND 세션당 상세 ≥ 2.0 |
| 🟠 **Inconclusive** | 전환율 20~30% (추가 데이터 필요) |
| 🔴 **Negative** | 전환율 < 20% OR 세션당 상세 < 1.0 |

### 5.4 의사결정 분기

| 결과 | 액션 |
|---|---|
| 🟢 Strong Positive | Phase-2에서 검색 경험 고도화 (자동완성, 추천 검색어, 맞춤 추천) 우선 투자 |
| 🟡 Positive | 현 방향 유지, 점진적 개선 |
| 🟠 Inconclusive | 추가 4주 데이터 수집 + 정성 인터뷰 5명 |
| 🔴 Negative | **근본적 재검토** — 검색 UX, 데이터 품질, 타깃 적합성 모두 의심. Phase-2 진입 전 사용자 인터뷰 우선. |

### 5.5 위협 요인 (Confounding Factors)

이 지표들이 **거짓 결과**를 낼 수 있는 요인들:

| 요인 | 영향 |
|---|---|
| 데이터 양 부족 | 검색해도 결과가 적어 전환율 저하 — H1과 무관 |
| 이미지 부재 | 카드 매력도 저하 — H1과 무관 |
| 카테고리 빠른 필터 사용 | 검색 경로를 우회 → `search_executed` 카운트 저하 |
| 직접 큐레이션 클릭 | 검색 거치지 않음 → 동일 영향 |

#### 보정 방안
- "카테고리/큐레이션 진입 → 상세" 경로도 별도 측정
- 사용자 의사결정 효율을 **모든 진입 경로 통합**으로 보조 측정

### 5.6 정성 검증 (보완)

정량 데이터로 부족한 부분은 **사용자 인터뷰**로 보완:

| 항목 | 방법 |
|---|---|
| 검색 만족도 | D 28~30 베타 사용자 5명 전화 인터뷰 |
| "기존 대비 시간 단축 체감" | 직접 질문 (5점 척도 + 자유 응답) |
| 미충족 니즈 | "VIVAC에서 못 찾은 정보가 있나요?" |

## 6. 가설 H2 — 온보딩 세그먼트 가치

### 6.1 명제 (정량화)

> "5단계 온보딩 설문으로 의미있는 사용자 세그먼트를 확보할 수 있다"
>
> 측정 가능 형태:
> - 온보딩 완료율 70% 이상
> - 5단계 모두 응답한 사용자가 50% 이상
> - 세그먼트(스타일×환경 조합) 분포의 다양성 확보

### 6.2 측정 지표

#### 주 지표

| 지표 | 정의 | 성공 기준 |
|---|---|---|
| **온보딩 완료율** | `onboarding_completed` / `onboarding_started` | 70% 이상 |
| **세그먼트 분포 다양성** | 각 스타일×환경 조합의 사용자 수 | 상위 5개 조합이 전체의 60~80% |

#### 보조 지표

| 지표 | 정의 |
|---|---|
| 단계별 이탈률 | step별 진입 → 완료 전환율 |
| 평균 완료 시간 | `onboarding_completed.total_duration_ms` 중앙값 |
| 건너뛰기 비율 | step별 `onboarding_step_skipped` 비율 |
| 응답 수정 빈도 | `onboarding_step_back` 발생 비율 |

### 6.3 세그먼트 다양성 측정 방법

#### 6.3.1 분포 분석

```
스타일 (5종) × 환경 (6종) = 30개 조합 가능

각 조합의 사용자 수 측정:
[UL × 산숲]: 35%
[종주장거리 × 산숲]: 18%
[베이스캠핑 × 계곡]: 12%
[UL × 노지]: 9%
[차박 × 강호수]: 8%
... (나머지 18%)
```

#### 6.3.2 다양성 지표

**Shannon Diversity Index** 활용:
- 1개 조합에 사용자가 몰리면 낮은 점수
- 여러 조합에 균등 분포하면 높은 점수

목표: **충분한 다양성** (특정 조합이 70% 이상 차지하지 않음)

### 6.4 성공 기준

| 등급 | 기준 |
|---|---|
| 🟢 **Strong Positive** | 완료율 ≥ 80% AND 상위 5조합이 60~80% AND 평균 시간 ≤ 60초 |
| 🟡 **Positive** | 완료율 ≥ 70% AND 다양성 충분 |
| 🟠 **Inconclusive** | 완료율 50~70% |
| 🔴 **Negative** | 완료율 < 50% OR 1~2개 조합에 90% 이상 집중 |

### 6.5 의사결정 분기

| 결과 | 액션 |
|---|---|
| 🟢 Strong Positive | Phase-2에서 추천 알고리즘 본격 개발, 세그먼트 기반 마케팅 |
| 🟡 Positive | 현 5단계 유지, 응답 데이터를 추천 알고리즘 학습에 활용 |
| 🟠 Inconclusive | 단계 수 축소 검토 (5→3), 카피 개선, 이탈 단계 정성 분석 |
| 🔴 Negative | **온보딩 전략 재검토** — 강제 온보딩 정책 자체의 문제 가능성, A/B 테스트 (Phase-2) |

### 6.6 단계별 이탈 분석

각 step의 이탈률을 모니터링하여 **문제 단계** 식별:

```
Step 1 진입: 100%
Step 1 완료: ?% — 입문 단계 이탈 (가입 동기 약함?)
Step 2 진입: ?%
Step 2 완료: ?% — 다중 선택 부담?
Step 3 완료: ?%
Step 4 완료: ?%
Step 5 완료: ?% (= 온보딩 완료율)
```

> 💡 어느 단계에서 이탈이 큰지에 따라 개선 방향이 다름.

### 6.7 위협 요인

| 요인 | 영향 |
|---|---|
| 마케팅 채널 편향 | 특정 페르소나만 유입 → 세그먼트 다양성 저하 |
| 옵션 라벨 모호함 | 사용자가 잘못 응답 → 데이터 품질 저하 |
| 첫 사용자 인구 적음 | 통계적 신뢰도 부족 |

### 6.8 정성 검증

| 항목 | 방법 |
|---|---|
| 단계별 이탈 이유 | 정성 인터뷰 |
| 응답 카피 명확성 | 5명 사용성 테스트 (Think Aloud) |
| 답변과 실제 행동 일치도 | 사용자 응답 vs 실제 검색/조회 패턴 비교 |

## 7. 가설 H3 — 카테고리 vs 검색 선호도

### 7.1 명제 (정량화)

> "BPL/UL 백패커는 자유 텍스트 검색보다 카테고리 빠른 필터를 더 선호한다"
>
> 측정 가능 형태:
> - 카테고리 클릭이 텍스트 검색의 **1.5배 이상**
> - 카테고리를 통한 상세 진입 전환율이 검색 대비 동등 이상

### 7.2 측정 지표

#### 주 지표

| 지표 | 정의 |
|---|---|
| **카테고리 사용 비율** | `category_filter_clicked` / (`category_filter_clicked` + `search_executed`) |
| **검색 사용 비율** | 1 - 카테고리 사용 비율 |

#### 보조 지표

| 지표 | 정의 |
|---|---|
| 경로별 상세 진입 전환율 | 카테고리 → 상세 vs 검색 → 상세 |
| 경로별 세션 길이 | 어느 경로 사용자가 더 오래 머무는가 |
| 카테고리별 클릭 분포 | 6개 카테고리 중 어느 게 인기 |

### 7.3 성공 기준

| 등급 | 기준 |
|---|---|
| 🟢 **Strong Positive** | 카테고리 비율 ≥ 70% |
| 🟡 **Positive** | 카테고리 비율 ≥ 60% (1.5배) |
| 🟠 **Inconclusive** | 카테고리 비율 40~60% (비등) |
| 🔴 **Negative** | 카테고리 비율 < 40% |

### 7.4 의사결정 분기

| 결과 | 액션 |
|---|---|
| 🟢 Strong Positive | Phase-2: 카테고리 확장 (서브 카테고리, 조합 카테고리), 검색은 보조 |
| 🟡 Positive | 카테고리 UI 강화, 더 많은 카테고리 추가 검토 |
| 🟠 Inconclusive | 두 경로 모두 유지, 사용자별 선호 분기 분석 |
| 🔴 Negative | 검색 경험 강화 우선 — 자동완성, 추천 키워드, 검색 결과 개선 |

### 7.5 카테고리별 인기도

가설 외에 **부가 인사이트**로 다음을 분석:

```
6개 카테고리 클릭 분포:
- 산·숲: 35%
- 바다: 22%
- 계곡: 18%
- 강·호수: 10%
- 노지: 10%
- 국립공원: 5%
```

→ **클릭 0% 카테고리는 제거 검토**, **상위 카테고리는 세분화 검토**

### 7.6 위협 요인

| 요인 | 영향 |
|---|---|
| 카테고리 매핑 오류 (B4) | 카테고리 클릭 → 결과 부적절 → 다시 검색 |
| 검색바 위치/크기 | UI에 따라 검색 인지도 영향 |
| 카테고리 단어 매력도 | "노지"처럼 백패커에게 익숙한 단어 vs 일반 단어 |

### 7.7 보완 분석

#### 7.7.1 시간대별/요일별 패턴
- 평일 vs 주말 사용 패턴 차이
- 출퇴근 시간대 vs 여가 시간대 사용 의도 차이

#### 7.7.2 사용자 세그먼트별 패턴
- UL 백패커 vs 베이스캠핑 백패커의 카테고리 vs 검색 선호도
- 경험 수준별 차이 (입문자 vs 고수)

## 9. 베타 사용자 정성 인터뷰 계획

정량 데이터를 보완할 정성 인터뷰 프로토콜.

### 9.1 인터뷰 대상

| 코호트 | 인원 | 선정 기준 |
|---|---|---|
| 활성 사용자 | 3명 | 가입 후 5회 이상 세종, 3회 이상 상세 진입 |
| 이탈 사용자 | 2명 | 가입 후 1주일 미접속 |
| 미가입 이탈 | 2명 | 락 모달 본 후 미가입 (이메일 미보유로 어려울 수 있음 → 광고 채널 활용) |

### 9.2 인터뷰 시점

| 시점 | 인터뷰 |
|---|---|
| D 28~30 | 1차 정성 인터뷰 |
| D 56~60 | 2차 (Phase-2 기획 직전) |

### 9.3 인터뷰 프로토콜 (활성 사용자 기준 30분)

```
[5분] 라포 형성 + 백패킹 경험 일반 질문
```

## 10. 실패 시나리오와 대응

### 10.1 모든 가설 Negative

```
H1 ❌ + H2 ❌ + H3 ❌
```

**원인 가능성**:
- 타깃 시장 자체가 작거나 잘못 정의됨
- 핵심 가치 제안이 부적절
- 데이터 품질이 사용 가치를 만들지 못함

**대응**:
1. **즉시 Phase-2 진입 보류**
2. 정성 인터뷰 10명 이상 집중 진행
3. 피벗 가능성 검토 (타깃 변경, 핵심 가치 재정의)

### 10.2 일부 Negative

```
H1 🟢 + H2 🟢 + H3 🔴
```

**대응**: 카테고리 우선순위 조정, 검색 강화에 더 투자.

```
H1 🔴 + H2 🟢 + H3 🟢
```

**대응**: 데이터/검색 품질이 핵심 문제. 카테고리/온보딩이 좋아도 검색 결과 후 의사결정에 도움 안 되면 가치 부족. ETL 정규화 우선.

### 10.3 Inconclusive 다수

데이터 부족 → 검증 기간 4주 추가 + 마케팅으로 트래픽 확보.

## 11. 측정 무결성 (Data Integrity)

### 11.1 검증 전 사전 체크

| 체크 항목 | 기준 |
|---|---|
| 모든 이벤트 정상 발화 | 출시 후 D 1~3 검증 |
| 사용자 식별 정상 | anonymous → user 머지 동작 |
| 슈퍼 프로퍼티 부착 | `user_state` 모든 이벤트에 포함 |
| 봇 트래픽 필터링 | GA4/PostHog bot filter 활성 |

### 11.2 데이터 클렌징

분석 시 다음 데이터는 제외:
- 내부 테스트 사용자 (이메일 도메인 기반 필터)
- 봇 트래픽 (User-Agent 기반)
- 비정상 세션 (1초 미만 / 12시간 이상)

### 11.3 통계적 신뢰도

| 표본 크기 | 신뢰 수준 |
|---|---|
| < 50명 | 참고 수준 |
| 50~200명 | 방향성 판단 |
| 200~500명 | 의사결정 가능 |
| 500명 이상 | 통계적으로 유의미 |

> 💡 Phase-1 베타 규모에서 표본이 작을 가능성 높음. 결론을 단정하지 말고 **방향성**으로 활용.
