## 2. 공통 디자인 원칙 (전 화면 공통)

### 2.1 디바이스 및 뷰포트
- **Primary Target**: 모바일 (375px ~ 430px width)
- **Secondary**: 태블릿/데스크탑 (반응형)
- **Safe Area**: iOS notch / Android status bar / 홈 인디케이터 대응

### 2.2 인터랙션 원칙
- **터치 타겟 최소 크기**: 44×44pt
- **모달/시트 닫기**: 배경 탭 + 닫기 버튼 양방향 지원
- **로딩 상태**: 모든 비동기 작업에 스켈레톤 또는 스피너 필수
- **에러 상태**: 토스트 또는 인라인 메시지로 명시
- **버튼 비활성 상태**: 시각적으로 명확히 구분 (opacity 또는 색상)

### 2.3 다크모드 (향후 확장)
- Phase-1엔 라이트모드만 구현
- 단, 디자인 토큰은 **CSS 변수 기반으로 변수화 유지** — 향후 다크모드 활성화 시 변수 값만 추가하면 됨

### 2.4 카피 톤앤매너
- 친근한 반말 톤 ("어디로 떠날까요?")
- 백패커 정서에 맞는 자연 친화적 표현
- 기능 설명보다 가치 중심 ("내 취향 알려주기" > "5단계 설문 작성")

| 항목 | 내용 |
|---|---|
| URL | `/login?redirect=...` |
| 화면 ID | `screen.login` |
| 접근 가능 상태 | S0 (S1~S3는 자동 라우팅) |
| 핵심 목적 | 구글 OAuth 로그인 |
| 핵심 KPI | 로그인 성공률, 페이지 도달 → 로그인 완료 전환율 |

#### 3.2.2 화면 구조

```
┌─────────────────────────┐
│ [← 뒤로가기]            │ ← 헤더
│                         │
│ [로고]                  │
│                         │
│ 헤드라인                │
│ 서브 카피               │
│                         │
│ ┌───────────────────┐  │
│ │ [G] 구글로 시작하기│  │ ← Primary CTA
│ └───────────────────┘  │
│                         │
│ 약관/개인정보 안내      │ ← 가입 동의 명시
│                         │
└─────────────────────────┘
```

#### 3.2.3 컴포넌트 명세

| 컴포넌트 | 내용 | 비고 |
|---|---|---|
| 뒤로가기 버튼 | 이전 페이지로 복귀 | 랜딩 또는 락 모달 호출 페이지 |
| 헤드라인 | "백패커 여정을 시작해볼까요?" | 카피 협의 가능 |
| 서브 카피 | "구글 계정으로 간편하게 시작하세요" | |
| 구글 로그인 버튼 | 구글 공식 가이드라인 준수 | [Google Sign-In Branding](https://developers.google.com/identity/branding-guidelines) |
| 약관/개인정보 안내 | "시작하기를 누르면 [서비스 이용약관] 및 [개인정보 처리방침]에 동의하게 됩니다" | 링크는 별도 페이지로 |

#### 3.2.4 인터랙션 명세

| 액션 | 동작 |
|---|---|
| 구글 로그인 버튼 탭 | 구글 OAuth 팝업/리다이렉트 시작 |
| OAuth 성공 콜백 | `/auth/callback`으로 진입 → 사용자 상태 판별 → 분기 |
| OAuth 실패/취소 | 이전 페이지로 복귀 (sessionStorage redirect 활용), 토스트 "로그인이 취소되었습니다" |
| 뒤로가기 | 브라우저 히스토리 기반 복귀, 없으면 랜딩으로 |
| 약관 링크 탭 | 새 탭으로 약관 페이지 열기 (Phase-1엔 정적 페이지) |

#### 3.2.5 OAuth 콜백 처리

`/auth/callback` 라우트에서 다음 처리:

```
1. URL의 OAuth code 추출
2. 백엔드 /api/v1/auth/google에 code 전달
3. 백엔드 응답: { token, user: { onboarding_completed_at, completed_steps } }
4. 토큰 저장 (httpOnly 쿠키 권장, 또는 sessionStorage)
5. 사용자 상태 판별:
   - S1 (completed_steps === 0) → /onboarding/1
   - S2 (completed_steps > 0) → /onboarding/[next]
   - S3 (completed_at !== null) → redirect 파라미터 또는 /home
6. 로딩 화면 표시 중 처리 완료
```

#### 3.2.6 트래킹 이벤트

| 이벤트 | 트리거 | 속성 |
|---|---|---|
| `login_viewed` | 페이지 진입 | `redirect_url` |
| `login_attempted` | 구글 버튼 탭 | `provider: "google"` |
| `login_succeeded` | OAuth 성공 | `provider`, `is_new_user` |
| `login_failed` | OAuth 실패 | `provider`, `error_code` |

#### 3.2.7 엣지 케이스

| 케이스 | 처리 |
|---|---|
| OAuth 팝업 차단됨 | 토스트 안내 + 팝업 허용 가이드 |
| OAuth 콜백 중 네트워크 단절 | 에러 페이지 + "다시 시도하기" |
| redirect URL이 검증 실패 (보안 정책 위반) | sessionStorage/쿼리 redirect 무시, 홈으로 fallback |
| 이미 로그인된 상태로 진입 | 사용자 상태에 따라 자동 라우팅 |

### 🟦 화면 3. 온보딩 5단계 (공통 구조)

#### 3.3.1 화면 개요

| 항목 | 내용 |
|---|---|
| URL | `/onboarding/[step]` (step: 1~5) |
| 화면 ID | `screen.onboarding.step.[1~5]` |
| 접근 가능 상태 | S1, S2 (S0는 로그인으로, S3는 홈으로 redirect) |
| 핵심 목적 | 사용자 선호도 데이터 수집 |
| 핵심 KPI | 단계별 이탈률, 전체 완료율, 완료 시간 |

#### 3.3.2 공통 화면 구조

```
┌─────────────────────────┐
│ [← 이전] [1/5]   [건너뛰기]│ ← 헤더 (Step 1은 [← 이전] 비활성)
│ ━━━━━━━━━░░░░░░         │ ← 진행률 바
│                         │
│ 질문 헤드라인           │
│ 서브 카피 (선택 안내)    │
│                         │
│ ┌───────────────────┐  │
│ │ 옵션 1            │  │
│ └───────────────────┘  │
│ ┌───────────────────┐  │
│ │ 옵션 2            │  │ ← 선택 시 강조
│ └───────────────────┘  │
│ ┌───────────────────┐  │
│ │ 옵션 N            │  │
│ └───────────────────┘  │
│                         │
│ ┌───────────────────┐  │
│ │ [다음] / [완료]   │  │ ← 옵션 선택 후 활성
│ └───────────────────┘  │
└─────────────────────────┘
```

#### 3.3.3 공통 컴포넌트 명세

| 컴포넌트 | 동작 |
|---|---|
| **이전 버튼** | Step 1: 비활성 / Step 2~5: 이전 단계로 이동 (기존 응답 자동 표시) |
| **진행 표시기** | "1/5" 텍스트 + 프로그레스 바 |
| **건너뛰기 버튼** | 응답 없이 다음 단계로 (해당 step 응답 = null) |
| **질문 헤드라인** | 24~28pt bold, 한 줄 또는 두 줄 |
| **서브 카피** | 다중 선택의 경우 "최대 N개 선택" 표기 |
| **옵션 카드** | 단일/다중 선택 모두 카드 형태, 선택 시 색상 + 체크 아이콘 |
| **다음 버튼** | Step 1~4: "다음" / Step 5: "완료" |

#### 3.3.4 단계 이동 시 데이터 처리

| 액션 | 백엔드 처리 |
|---|---|
| "다음" 클릭 | 현재 단계 응답 저장 + 다음 단계로 이동 |
| "이전" 클릭 | 현재 단계 응답 저장 (사용자 변경 보존) + 이전 단계로 이동 |
| "건너뛰기" 클릭 | 현재 단계 응답 = null로 저장 + 다음 단계로 이동 |
| Step 5 "완료" 클릭 | 응답 저장 + `onboarding_completed_at` 기록 + 리워드 화면 |

#### 3.3.5 온보딩 수정 정책

- **온보딩 진행 중 (S1/S2)**: 이전 단계로 이동 + 응답 수정 가능
- **온보딩 완료 후 (S3)**: 수정 불가 (Phase-2에서 마이페이지 통해 가능)
- **이전 버튼 위치**: 상단 좌측 (모바일 표준)
- **이전 응답 자동 표시**: 사용자 재선택 부담 감소
- **Step 1에서 이전 버튼**: 비활성 (이탈 방지)
- **이전 클릭 시 데이터 저장**: 현재 단계 응답 보존
- **수정 후 재진행**: 순차 진행 (스킵 없음)

| 액션 | 동작 |
|---|---|
| 옵션 카드 탭 (단일) | 선택 상태 토글, 버튼 활성화 |
| 옵션 카드 탭 (다중) | 추가 선택, 최대치 도달 시 추가 선택 차단 + 토스트 "최대 N개까지 선택 가능" |
| 최대 도달 후 다른 옵션 탭 | 토스트 안내 (선택 무시) |
| 다음 버튼 탭 (응답 없음) | 비활성 (탭 무반응) |
| 다음 버튼 탭 (응답 있음) | 응답 저장 + 다음 단계 이동 |
| 이전 버튼 탭 | 현재 응답 저장 + 이전 단계 이동, 이전 응답 자동 표시 |
| 건너뛰기 탭 | 현재 응답 null 저장 + 다음 단계 이동 |
| 완료 버튼 탭 (Step 5) | 최종 저장 + 리워드 화면으로 이동 |

#### 3.3.8 트래킹 이벤트

| 이벤트 | 트리거 | 속성 |
|---|---|---|
| `onboarding_step_viewed` | 각 단계 진입 | `step_number` |
| `onboarding_step_completed` | 다음 버튼 탭 | `step_number`, `answer`, `duration_ms` |
| `onboarding_step_skipped` | 건너뛰기 탭 | `step_number` |
| `onboarding_step_back` | 이전 버튼 탭 | `step_number` (이동 전 step) |
| `onboarding_completed` | Step 5 완료 | `total_duration_ms`, `skipped_count`, `answers` (요약) |
| `onboarding_abandoned` | 페이지 이탈 (24시간 경과 후 미복귀) | `last_step` |

#### 3.3.9 엣지 케이스

| 케이스 | 처리 |
|---|---|
| 응답 저장 API 실패 | 재시도 (최대 3회), 실패 시 인라인 에러 + "다시 시도하기" |
| 단계 이동 중 네트워크 단절 | 응답을 로컬에 임시 저장, 복구 시 자동 재전송 |
| Step 5 완료 후 onboarding_completed_at 저장 실패 | 리워드 화면 진입 차단, 재시도 안내 |
| 사용자가 직접 URL 변경하여 잘못된 step 진입 | 현재 진행 중인 step으로 자동 redirect |
| 다중 선택에서 최대치 도달 후 선택 해제 → 다른 옵션 선택 | 정상 동작 (해제로 빈자리 확보 후 추가) |

### 🟦 화면 4. 리워드 모먼트

#### 3.4.1 화면 개요

| 항목 | 내용 |
|---|---|
| URL | `/onboarding/complete` |
| 화면 ID | `screen.onboarding.complete` |
| 접근 가능 상태 | S3 진입 직후 1회만 (이후 재접근 시 `/home`으로 redirect) |

| 핵심 KPI | 화면 노출 → 홈 진입 시간, SNS 공유율 (향후 확장) |

#### 3.4.2 화면 구조

```
┌─────────────────────────┐
│                         │
│ [성공 애니메이션]        │ ← Lottie 또는 CSS 애니메이션
│                         │
│ "OO님은"                │
│ "[UL/경량]을 사랑하는"   │ ← 동적 카피
│ "[산·숲] 백패커시군요!"  │
│                         │
│ [세그먼트 시각화]        │ ← 아이콘/이미지 조합
│                         │
│ 안내 카피                │ ← "맞춤 장소를 찾아드릴게요"
│                         │
│ ┌───────────────────┐  │
│ │ [내 장소 보러가기] │  │ ← Primary CTA
│ └───────────────────┘  │
│                         │
└─────────────────────────┘
```

#### 3.4.3 동적 카피 생성 규칙

```
"{nickname}님은 {style_label}을 사랑하는 {environment_label} 백패커시군요!"

예시:
- "민혁님은 UL/경량을 사랑하는 산·숲 백패커시군요!"
- "민혁님은 종주·장거리를 즐기는 계곡 백패커시군요!"
```

#### 3.4.4 카피 변형 처리

| 케이스 | 처리 |
|---|---|
| Step 2 (스타일) 응답 없음 | "{nickname}님은 {environment_label}을 사랑하는 백패커시군요!" |
| Step 3 (환경) 응답 없음 | "{nickname}님은 {style_label}을 즐기는 백패커시군요!" |
| 둘 다 응답 없음 | "{nickname}님, 환영합니다!" |
| 다중 선택의 경우 | 첫 번째 선택만 표시 (시각적 단순성) |

#### 3.4.5 컴포넌트 명세

| 컴포넌트 | 내용 |
|---|---|
| 성공 애니메이션 | Lottie 또는 CSS keyframe (1초 내외) |
| 동적 카피 | 위 규칙 기반 생성 |
| 세그먼트 시각화 | 선택한 환경의 일러스트 + 스타일 아이콘 (디자이너 협의) |
| 안내 카피 | "내 취향에 맞는 장소를 찾아드릴게요" |
| Primary CTA | "내 장소 보러가기" → redirect URL 또는 `/home` |

#### 3.4.6 인터랙션 명세

| 액션 | 동작 |
|---|---|
| 진입 시 | 자동 1초 노출 후 CTA 활성화 (즉시 스킵 방지) |
| CTA 탭 | redirect 파라미터 적용 → 없으면 `/home` |
| 화면 진입 후 5초 무반응 | 자동 redirect (사용자 이탈 방지) |
| 재접근 시도 (S3 상태에서 직접 URL 입력) | `/home`으로 redirect (1회성 화면) |

#### 3.4.7 트래킹 이벤트

| 이벤트 | 트리거 | 속성 |
|---|---|---|
| `reward_moment_viewed` | 페이지 진입 | `segment` (예: "ultralight_mountain") |
| `reward_moment_cta_clicked` | CTA 탭 | `dwell_time_ms` |
| `reward_moment_auto_redirected` | 5초 무반응 | `segment` |

#### 3.4.8 향후 확장 (Phase-2+)

- SNS 공유 버튼 (Instagram 스토리, 카카오톡)
- 캡쳐 가능한 카드 형태의 시각 요소

### 🟦 화면 5. 락 모달 (Value Lock Modal)

#### 3.5.1 화면 개요

| 항목 | 내용 |
|---|---|
| 화면 ID | `modal.value_lock` |
| 노출 트리거 | S0 사용자가 락된 영역 탭 |
| 핵심 목적 | 가입+온보딩 유도 |

#### 3.5.2 화면 구조 (Bottom Sheet)

```
┌─────────────────────────┐
│ (배경 어둡게)            │
│                         │
│                         │
├─────────────────────────┤
│ ───                     │ ← Drag handle
│                         │
│ [자물쇠/일러스트 아이콘] │

│ │ [가입하고 확인하기]│  │ ← Primary CTA

│                         │
```

#### 3.5.3 락 종류별 카피 변형

| 락 종류 | 헤드라인 | 서브 카피 |
|---|---|---|
| Tier 2 정보 블러 | "더 자세한 정보가 궁금하신가요?" | "5단계 설문으로 내 취향을 알려주시면 모든 정보를 보여드릴게요" |
| 예약 CTA 락 | "예약 정보를 확인하시려나요?" | "가입 후 모든 예약 정보를 확인하실 수 있어요" |
| 외부 링크 CTA 락 | "더 알아보고 싶으신가요?" | "가입 후 공식 홈페이지로 바로 이동할 수 있어요" |

#### 3.5.4 컴포넌트 명세

| 컴포넌트 | 내용 |
|---|---|
| Bottom Sheet 컨테이너 | 하단에서 슬라이드업, drag handle 제공 |
| Drag Handle | 아래로 드래그하여 닫기 가능 |
| 일러스트 영역 | 자물쇠 또는 BI 일러스트 (디자이너 협의) |
| 헤드라인 | 락 종류별 변형 |
| 서브 카피 | 락 종류별 변형 |
| Primary CTA | "가입하고 확인하기" → `/login?redirect=현재URL` |
| Secondary 닫기 | 모달 닫기 (sessionStorage 기록) |

#### 3.5.5 인터랙션 명세

| 액션 | 동작 |
|---|---|
| 락 영역 탭 (최초) | 모달 슬라이드업 |
| 락 영역 탭 (이미 닫은 후) | 동일 페이지에서는 모달 미노출 (sessionStorage 체크) |
| Primary CTA 탭 | `/login?redirect={현재URL}`로 이동 |
| 닫기 탭 / 배경 탭 / Drag Down | 모달 닫기 + sessionStorage에 `lock_dismissed_{place_id}_{lock_type}` 기록 |
| 페이지 새로고침 후 재진입 | sessionStorage 유지로 모달 재노출 안 함 (의도된 동작) |
| 다른 페이지로 이동 후 재진입 | 신규 페이지로 간주, 모달 재노출 가능 |

#### 3.5.6 sessionStorage 정책

```
키: lock_dismissed_{place_id}_{lock_type}
값: true
TTL: 세션 종료까지 유지
예시: lock_dismissed_abc123_tier2
```

#### 3.5.7 트래킹 이벤트

| 이벤트 | 트리거 | 속성 |
|---|---|---|
| `value_lock_triggered` | 모달 노출 | `place_id`, `lock_type` |
| `value_lock_cta_clicked` | Primary CTA 탭 | `place_id`, `lock_type` |
| `value_lock_dismissed` | 닫기 액션 | `place_id`, `lock_type`, `dismiss_method` (button/backdrop/drag) |
| `value_lock_to_signup_conversion` | 모달 → 로그인 → 온보딩 완료 깔때기 | (여러 이벤트 조합으로 분석) |

#### 3.5.8 엣지 케이스

| 케이스 | 처리 |
|---|---|
| 모달 노출 중 화면 회전 | 모달 상태 유지, 레이아웃만 재조정 |
| 모달 노출 중 뒤로가기 | 모달만 닫힘 (페이지 유지) |
| 매우 작은 뷰포트 | 모달이 화면 절반 이상 차지 시 카피 축약 또는 폰트 사이즈 조정 |
| 모달 표시 직후 즉시 닫기 (의도치 않은 탭) | 정상 처리 (sessionStorage 기록됨, 재노출 안 됨) |

## 4. 디자이너 추가 전달 사항

### 4.1 디자인 토큰 정의 필요 항목 (BI 작업과 병행)

| 토큰 카테고리 | 항목 |
|---|---|
| 컬러 | Primary, Secondary, Success, Warning, Error, Neutral 1~9 (다크모드 향후 확장 대비 변수화 유지) |
| 타이포 | Display, Heading 1~3, Body 1~2, Caption, Label |
| 간격 | Spacing 4, 8, 12, 16, 24, 32, 48, 64 |
| 그림자 | Elevation 1~5 |
| 라운드 | Radius 4, 8, 12, 16, full |
| 모션 | Duration short(150ms), medium(300ms), long(500ms) |

### 4.2 컴포넌트 우선순위 (디자인 시스템 작업)

phase-1에 필요한 핵심 컴포넌트:
1. Button (Primary / Secondary / Tertiary, 4 size)
2. Input (Text, Search)
3. Card (가로형 / 세로형)
4. Chip / Tag
5. Modal / Bottom Sheet
6. Toast
7. Progress Bar
8. Skeleton Loader
9. Avatar
10. Icon set (40개 이상)

### 4.3 일러스트 필요 영역

| 위치 | 용도 |
|---|---|
| 랜딩 미리보기 이미지 | 서비스 가치 시각화 |
| 온보딩 옵션 아이콘 | 환경/스타일 식별 |
| 리워드 모먼트 세그먼트 시각화 | 가입 완료 보상감 |
| 락 모달 일러스트 | 가입 동기 유발 |
| 이미지 부재 시 플레이스홀더 | 데이터 누락 시 |
| 빈 상태 (Empty State) | 검색 결과 없음 등 |
